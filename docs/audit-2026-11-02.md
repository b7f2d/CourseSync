# NUFE-Schedule 原生化与稳定性审查

审查日期：2026-11-02。范围：当前仓库的 `index.tsx`、`intent.tsx`、`widget.tsx`、`widget-data.ts`、原生输入组件、构建脚本与 GitHub Actions。保留 README 的简洁安装说明，本报告记录实现层面的边界。

## 交互必要性

| 功能 | 方案 | 审查结论 |
| --- | --- | --- |
| 账号及密码 | Scripting 原生 TextField + SecureField | 保留同屏输入、iOS 密码填充语义，删除多余 HTML 登录页 |
| 短信、TOTP、图形验证码、普通文本 | 原生输入控件 | 短信声明 oneTimeCode；图片可解码时原生同屏展示 |
| 普通提示、确认、异常恢复菜单 | iOS Dialog | 原本就是系统原生交互，无须再封装网页 |
| 日历绑定选择 | iOS Calendar chooser | 保留官方选择器及绑定所有权检查 |
| 刷新进度 | 原生 Navigation + ProgressView | 不再使用 WebView/百分比/反复更新阶段文本；仅在必须输入验证时收起 |
| 学校拼图滑块验证 | 仅保留隔离的 WebView | 不能使用普通 Slider 假装产生学校要求的触摸轨迹；须真机与学校服务验证后才能安全替换 |
| 旧版内置 ListWidget 渲染器 | 删除 | 当前 `widget.tsx` 已是唯一可用的小组件入口，旧代码从不执行 |

## 数据完整性和安全边界

- 登录密码：原生窗口返回内存值；仅在学校确认登录后按既有策略保存到同步的 Keychain；不写入课表镜像、日志、ZIP。
- Cookie、身份标识、设备信息：仍按原有逻辑限定为本机，widget 镜像使用固定允许字段，不引入凭据。
- 网络：官方学校域名白名单、HTTPS、跳转检查、Cookie 作用域验证均保留；无第三方账号托管或新增外部服务。
- 日历：绑定的日历 ID、课程所有权标记、事务日志、写入前备份、写后核对和异常恢复逻辑均未修改；不清空用户其他日历。
- 并发：沿用同步锁与事务接管检查；后台快捷指令不呈现账号/验证码/进度页。
- 滑块：唯一剩余 WebKit 使用非持久化实例与禁止外部加载的 CSP；轨迹需经过结构、长度与范围检查，在页面仍显示时提交消息桥，关闭后不再读取 JS，最终释放实例。

## 自动化验证

`Validate` 和 `Publish Stable Release` 均先执行 `node --test tests/*.test.cjs`；打包脚本必须把独立原生进度组件、登录组件及现有入口全部纳入 ZIP。测试涵盖原生输入、取消、回退授权、账号认证后才保存密码、非法滑块轨迹、进度页让位、定时任务无弹窗、课表镜像不含敏感字段、日历写入/回滚/重复导入/账号变更等。

自动测试无法验证实际设备的 SwiftUI 弹窗时序、iOS 密码/短信建议、苹果日历授权以及学校滑块的服务端判定。这些需要在安装新版后进行一次设备验收，不能把 CI 通过称为真机无故障。

## 建议的真机验收顺序

1. 直接「立即刷新」，确认原生进度页不闪烁，完成后仅出现一次结果。
2. 在「自动登录凭据」用原生表单选择已保存的学校账号，验证取消不会保存错误凭据。
3. 会话到期后，在前台输入短信/TOTP 或图片验证码；观察进度页先收起、验证完成后再显示。
4. 若遇到学校拼图验证，检查正常拖动和提交能否被学校接受；不成功时保留错误代码，不反复重试。
5. 校对 Apple 日历与小组件课程数量、时段、配色、当前课切换；重复刷新不应新增重复课程。
6. 通过快捷指令定时执行，确认无需原生弹窗且登录需要处理时保留旧课表并通知。

审查原则：优先删除重复/不可达实现，不更改已验证的同步和日历写入协议；只有真机确认稳定后才移除学校滑块的兼容路径。
